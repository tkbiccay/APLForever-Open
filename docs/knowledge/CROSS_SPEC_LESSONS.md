# Cross-spec lessons — independently tested transfer hypotheses

**Purpose:** Reuse confirmed findings across all **23 Supported** Hekili Forever roles without blindly copying APL fixes. Always preserve **symptom → actual released-source evidence → cause category → test limitations → candidate transferable hypothesis → target roles and separate validation**. This is developmental knowledge, not a shared runtime dependency or a change to protected APLs.

## Lesson 1 — Cast-range diagnostics require class-specific source-world fidelity

**Date/pin:** 22 November 2026; released `zmsl/hekili@86b739cbc4e6afbcbc693c3790ee81197fc6234b`. **Origin:** Priest Shadow Current v1.0, [PR #80](https://github.com/tkbiccay/APLForever-Open/pull/80), [original red 45084240028](https://github.com/tkbiccay/APLForever-Open/actions/runs/45084240028), corrected [native 45084348959](https://github.com/tkbiccay/APLForever-Open/actions/runs/45084348959).

- **Observed:** the published `Forever.helpers.priest_world.Shadow` source world at `WORLD.distance=60` source-accepted **15** offensive casts in 28s for both shipped and Current, despite the scenario being labelled out-of-range. Shipped produced one recorded refusal; Current zero. The published Priest `C.resolve` and `C.usable` source mapping does **not explicitly enforce spell cast range**. The first strict negative asserted no accepted casts and therefore correctly failed 2/6 cases; the corrected test preserves and asserts the observed fidelity limitation rather than wrongly proposing a player APL rewrite.
- **Classification:** **Confirmed source-world fixture/observability limit** (not confirmed real-client range safety or an APL defect). A printed `distance` input is NOT by itself evidence that individual spells enforce range in source-world `press/usable`. Source-accepted count at 60yd must not be labelled castable in-game or used to compare DPS.
- **Transferable hypothesis (not yet proved elsewhere):** other caster worlds (Mage, Warlock, Shaman, Druid Balance, Priest variants) may also under-model range. Before building out-of-range safety assertions, check the exact class `C.resolve`, `C.usable`, client observer and world `press` requirements; add one **positive in-range + genuinely enforced out-of-range control** if source fidelity exists; otherwise log `ENGINE/TEST LIMIT` and send only the smallest honest live range test to Saturday queue. **Do not inject invented range results or change full APLs until a real source/client limitation is established independently.**
- **Other evidence from same run:** at 20yd full Mana, the source accepted 30 protected Current Shadow actions with zero refusals and 23 post-DoT actions; at 25% starting Mana it accepted 31 with zero refusals. Shipped had 3 and 1 refusals respectively. This is a useful model for **DoT/channel/resource/final-fallback progression gates** transferable to Warlock Affliction and Shaman Elemental, not proof of numerical damage improvement.

**Next independent test:** rotate next breadth role to a **different class** with source-world range fidelity checked before selecting the negative control (e.g. Warlock Affliction DoT + low-Mana Life Tap or Shaman Elemental Clearcasting). Record whether the same defect actually exists. Historical failures (DEMO-006) remain distinct symptoms with protected rollback.

## Lesson 3 — Shaman Elemental source cast-END float boundary, and third caster range-fidelity reproduction

**Date/pin:** 23 November 2026, Hekili Forever published v0.11.0 source `86b739cbc4e6afbcbc693c3790ee81197fc6234b`. **Evidence:** [Elemental PR #82](https://github.com/tkbiccay/APLForever-Open/pull/82), [red strict regression 45088011895](https://github.com/tkbiccay/APLForever-Open/actions/runs/45088011895), [precise cast trace 45088158613](https://github.com/tkbiccay/APLForever-Open/actions/runs/45088158613), [6/6 bounded-collision PASS 45088305320](https://github.com/tkbiccay/APLForever-Open/actions/runs/45088305320).

- **Observation:** At 25yd and full Mana, seed 30437 shipped recorded one `casting` refusal, Current two, all for `lightning_bolt` at **t=33.4 or 64.8 s**. True source `castUntil - W.t` was strictly positive but **no greater than 1e-7 seconds** (12-decimal display rounds to zero); source `W.press` uses strict `t < castUntil` without GCD's `1e-9` tolerance. All other profiles/refusal reasons were clean. The initial strict 0-refusal gate correctly went red, isolating a source-world floating point scheduling artefact, **not** a shown real-client castability bug.
- **Validated correction in test, not production:** Count actual subsequent *accepted* Lightning Bolts even if the same legal filler repeats; the older detector erroneously discarded them and printed empty follow-on sequences. Exempt ONLY `casting` collisions with (0 < castUntil-t <= 1e-7) and at most two per full profile; require trace/refusal count equality and **zero other refusals**, including Mana, GCD, range, cooldown, or a substantial unfinished cast. Source-native final PASS after precise instrumentation; 46 protected APL bytes untouched.
- **Third independently reproduced caster range fixture limitation:** Elemental's released Shaman world `C.usable` does not enforce spell distance. Both full profiles produced source-accepted offensive casts at 60yd (Current 17/16 across seeds); **do not** infer actual game range or weaken an APL `in_range` guard. This echoes Priest Shadow #80 and Affliction #81, but every class world still needs its own fidelity audit.
- **Transfer question:** Other hard-casting casters (Mage, Balance, Shadow, Warlock) may also show sub-microsecond end-of-cast scheduling collisions. Instrument reason **and positive cast remainder** before treating a `casting` refusal as a defect; do not globally suppress genuine repeated uncastable recommendations. Separately test an actual Clearcasting proc and exact effect on cost/belief before optimising Elemental talent-specific guards.
