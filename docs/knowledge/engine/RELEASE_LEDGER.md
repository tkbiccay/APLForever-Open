## Standard release gate: verify, adapt, opportunistically improve

1. **Detect and pin:** query latest *published* release tag + resolved commit + release notes and diff against last source-native validated release. Retain old baseline. If no changed release, don't rerun matrix.
2. **Inventory:** diff `docs/wiki/`, expression/line-option grammar, registered class abilities/talents, shipped packs, core observability/forecast, settings and upstream tests. Ignore unreleased code. Source-of-truth is exact tag, not a local wiki clone or copied chat extract.
3. **Compatibility:** reproduce existing APL import/compile + selected active lists on new tagged native harness. Run high-impact source-native regression fixtures by changed subsystem, always including core final-fallback/repeated recommendation safety. Check **actual accepted presses vs waits/refusals**, not first-icon agreement alone. Batch unchanged checks and avoid 3+ seeds unless noise demands them.
4. **Classify:** *unchanged and passing* → preserve exact current APL; *test fixture defect* → repair fixture only; *new engine limitation* → mark and avoid fictional guards; *reproducible compatibility regression* → escalate and consider safe candidate/rollback. Do not automatically downgrade previously reported-working based on uncorroborated simulated evidence.
5. **Capability review:** verified new line options/class registrations may be exploited in a custom design, but require a clear mechanism, safe castability, fair default AND last-working comparison, complexity budget and reproducible net advantage or coverage benefit. Separate "engine feature works" from "our APL gets better using it".
6. **Promotion:** never replace the reported-working reference or mark Approved from CI/simulations. User in-game validation only for genuinely unreproducible questions; protect immutable hashes. Log source/test/decision/rollback.
7. **Update this entry:** date, tag/SHA, source/wiki deltas, impacted roles, exact test results/CI refs, open limitations, compatibility disposition (Not Run / Partial / Passed in Scenarios / Needs Retest / In-Game Validated), and next minimal task. Do not silently change a past version's results.
