# Reuse resolved issues across APLs — mandatory learning gate

**Effective 16 November 2026.** One resolved issue should improve the entire APLForever project **where the underlying cause genuinely transfers**. Reuse evidence, knowledge, fixtures and safe patterns rather than rediscovering them for each class. **A reusable lesson is not permission to copy a spell, guard, APL branch or expected outcome into another class without verification.**

**18 November role-based testing reuse:** DPS damage scenarios, Tank mitigation/threat/survival scenarios and Healer triage/mana/overheal scenarios can share **design and instrumentation** across different specs in the same role only when the actual Hekili engine/Belief visibility, kit, encounter assumptions and acceptance claims are independently valid. The five blocked healer APLs remain blocked. External WoWSims/SimC/Raidbots/AskMrRobot-style numerical simulations are **optional**, not required for an APL or a new universal CI workstream. Read [SIMULATION_POLICY.md](../SIMULATION_POLICY.md). Full standalone spec-specific APL files remain mandatory.

The source of truth remains the [live catalogue](../../../catalogue/roles.json), pinned [release ledger](../engine/RELEASE_LEDGER.md), [handover](../CONTINUATION_HANDOVER.md) and individual `Research_*`, `Tests_*`, `Changelog_*` and issue records. This page is a **cross-role index of proved techniques and applicability**, not a second status catalogue or a demand to write new code.

## Hard boundary: shared development knowledge, never shared APL runtime

- **Reuse:** root-cause analysis, source-verified mechanics, design concepts, test methodology, fixtures, CI/validator utilities and prior positive/negative evidence. These live in the repository for **development only**.
- **Never share at runtime:** partial APL files, cross-file `include`/`import` directives, common custom action lists/helper scripts, another role's priority or any custom APLForever file that must be installed for a different APL to work.
- **Deliver:** one **complete self-contained APL** per class/spec/role, with its own precombat, combat, cooldown/defensive lists, internal list definitions and safe final fallbacks. Any `call_action_list` target must exist **within the very same text file**. The built-in, source-verified Hekili Forever interpreter/class pack and supported WoW APIs are the unavoidable permitted engine dependencies.
- **Verify:** isolated import/compile from only that candidate file; list-call resolution, complete reachable tail and repeated decisions; explicit no-dependency check before delivering or promoting. A transferrable *mechanical idea* is independently implemented and verified within each role, never imported from another file.

**Rule of thumb: share how we learned and proved a fix; never share the code a player's APL requires in order to run.**

## Mandatory checkpoint when an issue is resolved

1. **Classify the actual root cause.** Separate *observed symptom*, *verified cause* and *hypotheses*; record whether it was the APL priority, source engine/state/registration, headless fixture/observer, CI/manifest, game/API visibility or simply unverified gameplay. Never turn a reported symptom into a proven class-wide defect.
2. **Search the catalogue by shared mechanism, not just class name.** Identify other *supported* roles that use the same engine interface, resource observer, list/toggle, rank/level gate, pet/form, cooldown or final fallback pattern. Compare exact released source and feature/ability unlocks. Include the equal-highest-priority **Druid Guardian/Feral Tank and Hunter Beast Mastery, then Feral DPS** first *when relevant*, not as an excuse to test irrelevant Druid mechanics.
3. **Make one explicit transfer decision:** **Reusable directly (method/tooling)**, **Candidate for targeted role validation (mechanics/APL logic)**, **Not applicable (different mechanics or engine)**, or **Unknown/blocked**. State *why*, who benefits, the evidence grade, exact pin, and what would falsify the transfer. Prefer reusing existing test fixtures and assertions to a separate new test for every spec.
4. **Choose the smallest decisive check for each relevant class of behaviour.** If an existing passing cross-role assertion already covers it on the same source, **stop**. Otherwise: inspect source → static full fallback/safety chain → one role-targeted native import/state-advanced test → broader regression only if a changed shared component warrants it → player-only live observation when native state cannot be faithfully modelled. Keep matched shipped and last-working comparisons as applicable. Use three seeds only for outcome-sensitive RNG/noise.
5. **Implement only after proof.** A general *test-method* fix can transfer directly; a **combat priority** change requires role-specific verified abilities, casts/costs/unlocks, toggles and risk-based validation, an independent complete revision, a protected rollback, and normal human approval. Do not bulk-create candidate APLs or silently alter Current/Checkpoints. No mass copy-paste of Retail/Classic/SoD assumptions.
6. **Close the loop in the existing record.** Add a short **Cross-APL transfer** note to the original issue/PR or `Tests_*`/knowledge entry: resolution ID, confirmed cause, affected/suggested roles, non-applicability, exact reuse/test links, evidence grade, next *single* check or **STOP**. Update this index **only when a new genuinely reusable rule emerges**; do not produce new duplicate documents or a 23-spec CI sweep for a settled fact.

### Compact resolution note template

```text
Symptom / confirmed root cause:
Pinned source and original evidence (PR/issue/CI):
Reusable unit: engine rule | test/fixture | safe APL pattern | class-only mechanic
Transfer decision: direct method | test one relevant role | not applicable | blocked
Target roles and exclusions (why):
Reused existing proof / smallest new test and result:
Safety/final-fallback/rollback impact:
Status: verified reusable / role-specific validation needed / experimental / not applicable
Next action or STOP:
```

**The measure of success is prevented duplicate investigation**, not the number of patterns, CI runs, or APL versions.
