**Mechanics:** [State.lua](https://github.com/zmsl/hekili/blob/v0.10.0/src/Hekili/Engine/Sim/State.lua#L2428) defines `tanking = role.tank and aggro`; [Activation.lua](https://github.com/zmsl/hekili/blob/v0.10.0/src/Hekili/Engine/Schema/Spec/Activation.lua#L122-L132) sources `role.tank` from client pseudo-specialisation, not selected Guardian APL. This can suppress v1.4 Roar with true aggro but DAMAGER client role. The earlier role-free group/time alternative wrongly recommended Roar on a grouped client reporting NO aggro, wasting 10 Rage and GCD. Source v1.5 changes **one expression only** to `aggro&((group&time>=5)|(target.is_boss&time>=4)|(solo&time>=12))`. Preserves original Bear Form, Roar known, within5, debuff-down, Rage-low 10-cost+10 reserve; all cooldowns, Barkskin native Defensives user off-switch, and full Maul/fallback chain exactly v1.4. No per-spec settings or health guesses.

The actual v1.5 file must pass independent **byte-exact comparison to in-memory candidate** and three accepted post-Roar actions in its source-native check; this is not yet a claimed pass.

**Default and working:** [Game-default source comparison 44713464837](https://github.com/tkbiccay/APLForever-Open/actions/runs/44713464837) gave shipped 0 Roars/18 accepted, reported-working v1.0 0/13, v1.4 0/13 on normal non-aggro group; note the sim-mode setting `maintain_demoralizing_roar` defaults **true in simulator**, false in game, so sim-only comparisons can be misleading. More accepted actions ≠ better output, threat or survival. No matched DPS/threat/mitigation superiority has been shown.

**Risk:** `aggro` is from `UnitThreatSituation("player")>1`, which may be unavailable in instances; v1.5 then safely abstains but may miss useful debuff uptime. Range, boss designation and Rage beliefs are imperfect. No real live cast, real role, 1–60, higher-Rage Maul or survival proof. This is source-native design, not consensus taken from Retail.
