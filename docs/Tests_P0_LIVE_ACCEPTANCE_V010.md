## Install without overwriting a working pack

1. On an actual **v0.10.0** client, record level, active talents/build, equipment, active APL name, main toggle states and active combat display. Preserve existing working APL (or exact existing draft) by leaving it untouched; do not import test code over it.
2. Open `/hekili` → **Priorities**. Enter a **new Priority Name** (e.g. `APLForever-Guardian-v1.4-TEST` or `APLForever-BM-v1.2-TEST`), choose the matching specialization and **Create New Pack**. Go to the pack's **Source** tab, paste the **entire file**, click **Import**, and inspect the **Import Log/Warnings**. Abort on an unknown action, unknown expression, error, or disabled required line.
3. Set **Active** on the *test pack only*. Ensure ability keybinds/action bar can cast the suggestions. Do not change per-spec checkbox/dropdown settings to make a test pass. Do not cast a cooldown, consumable or life-costly ability solely because an experiment wants a cast. Use level-appropriate **open-world mobs**; do not assume target dummies exist.
4. After the safe trial, **reselect the prior Active pack**. A green source-native test or screenshot does not change catalogue preferred/Approved status. [Official v0.10.0 tutorial](https://github.com/zmsl/hekili/blob/v0.10.0/docs/wiki/APL-Tutorial-Your-First-Custom-Priority.md) verifies this create-new-pack/Source/Import/Active flow.

## Guardian v1.4 — smallest *live* decisive cases

**Prerequisites:** Bear Form learned; Demoralising Roar known if testing upkeep; Fury/tank talents and buff setup recorded. If unlearned, mark NOT APPLICABLE, not FAIL.

1. **Short safe solo enemy:** observe opener + at least three **different combat events** (recommend → press if legal → next recommendation). For an ordinary ~9 s enemy, Roar should not displace useful main attacks merely because the Defensives toggle starts ON. The v1.4 solo tank branch uses time ≥12s; it is **not guaranteed to trigger** if `tanking` is hidden/false. Check real timing rather than fake health thresholds.
2. **Longer group tanking, only when naturally available:** with the user’s usual native toggles and *without enabling* `settings.maintain_demoralizing_roar`, observe a safe extended encounter where you are actually tanking. **New critical source finding:** v1.4 `group&tanking&time>=5` also requires **the client’s pseudo-specialisation role to be TANK**, not merely that you have aggro or selected a Guardian APL. Published source-native Guardian clients report DAMAGER, so that branch produced zero Roars in [role-gate source test 44713464837](https://github.com/tkbiccay/APLForever-Open/actions/runs/44713464837), despite an in-memory role-free variant producing one legal Roar. The actual game’s role remains unverified. Record whether v1.4 ever recommends Roar at sufficient Rage while the debuff is down; capture `/hek snap` if missing. **Do not manually alter addon settings or client role to force a pass.** A missing recommendation under a DAMAGER-role client is a **confirmed source-mechanism risk**, not an automatic PASS or proof of a hidden resource. Preserve v1.0 if you observe a regression. Do not disable defensive mitigation in an unsafe encounter.
3. **Barkskin native option:** if learned and a safe test exists, confirm it respects the Defensives toggle while ordinary tank upkeep does not. Do not trigger arbitrary defensives on a weak low-risk mob as a proof of improved survival. Confirm the first three **post-upkeep** recommendations; record cast acceptance, waits and any repeated no-progress icon.
4. If testing v1.0 to v1.4 fairly, match build/level/gear, enemy type, native toggles and resources as closely as gameplay permits. Preserve the exact v1.0 Reported Working APL; if a meaningful new regression occurs, **immediately reselect it**, regardless of simulation outputs.

**Unresolved limits:** target.range brackets can read true when unknown; the client-role-qualified `tanking` signal is unverified in the real game, and player health, damage and boss timing are hidden. **Hekili sim mode registers Roar maintenance ON while actual game default is OFF**, so only compare default/working packs under the same real game setting and do not enable that checkbox for normal play. High-Rage Maul positive remains separately blocked; do not present Roar tests as solving it.

## Hunter BM v1.2 — smallest *live* decisive cases

**Prerequisites:** hunter has a tamed companion and knows Call Pet/Revive Pet as applicable. If pet unavailable due quest/level, mark NOT APPLICABLE.

1. **Pet absent but callable, out of combat:** expect Call Pet. Actually cast it normally, confirm the main pet arrives and is alive, then record **at least three distinct real post-cast recommendation evaluations and the actual accepted abilities**. Expect the *recovery* icon to stop. The class explicitly does NOT simulate an arriving pet inside its forecast; it relies on real client `UnitExists/UnitIsDead` and `IsSpellUsable`.
2. **Pet dead (only if naturally dead):** if Revive Pet is learned, usable and you can safely complete its cast/mana cost, observe Revive → actual revived pet → first three next actions. **Do not kill a pet just to run a regression test.** If pet recovery fails or repeats while an alive pet is reported, capture a snapshot.
3. **Ranged positioning (optional):** in a naturally safe 6–8 yd spacing, v1.2 can recommend **Summon Hawk** (0–35 yd) but should never repeatedly recommend an uncastable **Arcane/Serpent Sting** (8–35 yd minimum). Source-native at six yards found v1.2 modelled Hawk casts legal while the shipped Turret repeatedly suggested an out-of-range Sting. Actual auto-shot timing at that distance is **not reliably modelled**; observe rather than infer.
4. Leave native Major ON/OFF preference untouched. Bestial Wrath/Rapid Fire are native Cooldowns-gated; ordinary pet upkeep, hawks and shots are independent. A repeated **ready, no-progress** icon after real state advances is a failure. A deliberate `wait` for Mana/CD is **not** the same thing.

**Unresolved limits:** source headless [run 44706899530](https://github.com/tkbiccay/APLForever-Open/actions/runs/44706899530) confirmed **4/4 controlled client-state transitions**, **not actual accepted Call/Revive or real pet arrival**. Pet damage, live pathing, facing, Auto Shot suppression and output remain unmeasured. Neither native HHA nor range-aware HHA hybrid is promoted; original v1.2 remains untouched.

## Evidence capture and strict decisions

Record **Build / Level / Talents / Gear / APL file revision+hash / Native toggle values / Mob/context / Time / Expected action / Recommended icon / Actually pressed and accepted? / Next 3 real post-action icons / Any repeat and wait**. A tiny 10–20s fight record is more valuable than unspecific “seems fine”.

When a recommendation is wrong, unusable, missing unexpectedly or stuck, enter `/hek snap` (or `/hekili snapshot`), open **/hekili → Snapshots (Troubleshooting)**, select the latest and copy the **complete** text. [Official troubleshooting reference](https://github.com/zmsl/hekili/blob/v0.10.0/docs/wiki/Reporting-A-Problem.md). The snapshot must show the *actual affected pack*, state and first priority chain; do not invent a source-world success.

Decision: **PASS** only when expected real casts/post-action recommendations are observed without critical safety or repeated-fallback failures; **FAIL/ROLLBACK** for meaningful reproducible regressions; **INCONCLUSIVE** for missing transitions or changed conditions; **NOT APPLICABLE** when level/talent does not support an ability; **ENGINE LIMITATION** when Forever cannot expose the crucial state. Game observation can support `In-Game Validated` after required broader risks are covered; **Approved** remains a separate maintainer decision with fair shipped/default/last-working comparison and no critical issues.

**Do not require a user to install development files, enable custom addon toggles, run GitHub CI, write Lua or run a dedicated private server.** Keep the real-player requirement minimal and let our public source-native CI do everything faithful first.
