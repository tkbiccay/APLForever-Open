# Headless-first release validation — exact evidence, not automatic approval

**Source of truth:** 28 catalogue roles / 34 protected SHA-256 APL revisions on 19 November 2026; current external Hekili Forever release [v0.10.0](https://github.com/zmsl/hekili/releases/tag/v0.10.0) at `3c2cf3e32472cc807b1ba29d992fc13a273da8ee`. Our main responsibilities are **our custom APLs**, not upstream Hekili code.

## What is now automated on every PR

`scripts/audit_apl_observability.py --check` reads **every catalogued APL, not only Current and Candidates**, confirms its hash and looks for known source-invisible or fixed-value expression families from the released [Forever APL conditions guide](https://github.com/zmsl/hekili/blob/v0.10.0/docs/wiki/APL-Conditions-On-Forever.md). It resolves literal `call_action_list` / `run_action_list` edges to separate **combat-reachable** from **precombat-only** conditions. Unlike upstream's phase-agnostic warning scanner, this identifies the Arms Bloodrage precombat health condition separately from Feral's actually dead in-combat health thresholds.

A **pinned exact-path/sha/rule/count historical debt file** (`docs/knowledge/engine/observability-baseline.json`) records 6 combat-health uses across immutable Feral v1.0/v1.1, one Arms precombat-health use and eleven `fight_remains` uses in the immutable **archived shipped/default** Warlock Demo comparator. No other matching hidden-state expressions were found in the 34 protected revisions. Their presence is **still known debt**, not a PASS or a safe APL; CI fails **any new, removed or changed** finding so legacy files cannot silently hide a new regression. A removed finding requires a separately reviewed baseline change, never a blanket waiver. New Candidates must avoid secret/fixed-value dependencies; an exceptional source-confirmed guard requires explicit review and targeted native evidence.

CI generates a full **28-role Markdown headless-evidence matrix** from source-catalogued bytes and `docs/knowledge/engine/headless-evidence.json`. Read the exact artefact `per-role-headless-evidence` on the [Validate public repository workflow](https://github.com/tkbiccay/APLForever-Open/actions/workflows/validate.yml); the same table appears in the GitHub job summary. The table distinguishes *preferred/current* from *latest Draft Candidate*, lists historic warnings and marks latest-release native tests **Not individually established** unless an explicit pinned run confirms the relevant scope. It never converts a green old release or failed broader gate into all-role compatibility.

## Already present: do not rebuild the test system

`scripts/validate_repository.py` already enforces 28-role schema, full APL import filenames/paths, current/rollback selection and hashes. `tests/native/aplforever_import_spec.lua` and `tests/native/aplforever_progress_spec.lua` already exercise source native import/compilation, Hekili output, actual accepted/refused casts and defined fallbacks. Guardian/Hunter source-native release/test suites already cover their own source states and toggles. Those are the basis for a future standard per-role evidence contract; no new generic DPS simulator or duplicated full all-role native suite is needed.

**Honest blocked areas (unchanged):** [Draft v0.10.0 all-role gate #13](https://github.com/tkbiccay/APLForever-Open/pull/13) remains RED/Partial on older Feral and Arms warnings. [Guardian high-Rage Maul #3](https://github.com/tkbiccay/APLForever-Open/issues/3) is **Blocked/Not Demonstrated**; the strict positive experiment stays separate, **not counted as passed via expected-fail**. Hunter BM actual Call/Revive pet arrival and real-state advancement are not proved by first-icon tests. No per-role source scope establishes actual survival/DPS advantage, all 1–60 boundaries, or In-Game Validated/Approved.

## Next vertical slice (after the linter)

Use **existing** pinned v0.10.0 Guardian and BM fixtures as the standard per-role contract: import errors, source-known ability, toggles ON/OFF, native accepted/refused events, three state-advanced first recommendations and end-of-chain after resource decline, plus shipped/default and exact reported-working comparisons. Each cell must include version SHA, test/CI URL, current or candidate revision/hash and status **Passed / Failed / Blocked / Not Run**. Add a positive test only when faithful source state makes it reachable; do not fake HP, Rage or pet arrival. Separate in-game snap/checklist for unobservable behaviour. Once P0 is proven, transfer the *test pattern* to the next affected role, never a shared runtime APL.
