## Default-first research and independent hypothesis

The shipped source Guardian WoWSims-derived profile and working v1.0 use NO automatic Barkskin actions in the tested full-file source worlds. v1.5 has verified standalone Demoralising Roar in a true client-aggro scenario and a native `toggle.defensives` guarded Barkskin branch; prior v0.11 Roar 4/4 native test verified accepted/landed/resisted debuffs but the **Guardian source-world test kit lacked Barkskin**, rendering any `Defensives OFF => no Barkskin` evidence vacuous. Actual class [Druid.lua](https://github.com/zmsl/hekili/blob/v0.11.0/src/Hekili_Druid/Druid.lua) defines **Barkskin spell/aura 22812, 15-second aura, 60-second cooldown, spell GCD and native `toggle="defensives"`**. The [engine State.lua](https://github.com/zmsl/hekili/blob/v0.11.0/src/Hekili/Engine/Sim/State.lua) exposes `gcd.remains`. Published [druid_loop_world.lua](https://github.com/zmsl/hekili/blob/v0.11.0/tests/Forever/helpers/druid_loop_world.lua) maps other actions but **not Barkskin**, and [wowsims.content](https://github.com/zmsl/hekili/blob/v0.11.0/tests/Forever/helpers/wowsims.lua) provides a verified test-only added class `kit` interface.

**Hypothesis:** source-full v1.5's `action.barkskin.ready` becomes true on cooldown expiry without guaranteeing the actual player GCD is ready. A strict explicit `gcd.remains=0` in **Barkskin's own branch** should eliminate repeated premature GCD-refused first icons while retaining actual casts and all existing action fallbacks. This is a **single verified timing guard**, not a generalized health/mitigation policy. It is not evidence of all-class optimality; cross-spec reuse must independently prove the timing and syntax.

## Released-source kit adapter, not fabricated combat

The new native test uses the published `wowsims.content(..., kit={"barkskin"})` and an isolated, restored-after-each-test helper mapping for the *already registered real class action*, to the published generic `W.applyAura` with Barkskin's actual 15s duration/ID. Native source resolve supplies **the actual 60s cooldown, spell GCD, known ranks, native toggle and world clock**. This mapping is transparent **test infrastructure only**: it is not in a saved APL, addon engine, player environment, or reusable runtime file, and it **does not model damage reduction, incoming damage severity or survival**. The test controls source fake client role DAMAGER, client aggro true/false and 4/6yd distance; source world generates actual casts, mob swings, and Rage normally.

The first test [red 44943640179](https://github.com/tkbiccay/APLForever-Open/actions/runs/44943640179) revealed **three native GCD refusals** for original full v1.5 in seed 30417, despite legal Barkskin casts at **1.8s and 62.4s**; source first icon at **61.8, 62.0, 62.2s** had `recommendedWait=0` but **true GCD remaining 0.5, 0.3, 0.1 seconds**. Seed30418 had none. Test-only `gcd.remains<=0.05` reduced **3→1**, because at 62.2s the source still reported a GCD refusal. Strict **`gcd.remains=0` reduced 3→0**, without changing *actual* Barkskin casts or post-Barkskin action count. [Strict in-memory full A/B 44944331232](https://github.com/tkbiccay/APLForever-Open/actions/runs/44944331232) **5/5 PASS**, 20 whole-profile world comparisons across 4yd true-threat seeds, native Defensive OFF, 6yd, and no synthetic client threat.

## Decision and risks

v1.6 is a new **fully independent 2,798-byte complete APL** with exactly one extra `&gcd.remains=0` on its Barkskin line versus byte-protected v1.5; all precombat, Roar, real Maul queue rules, defensive cooldown toggle, upkeep, damage and final rage-dump chain remain intact. This is justified by actual repeated first-icon refusals, not speculative DPS polishing. Only a source-native FULL stored-file rerun and client-side confirmation can validate it. The **shipped/default** and **reported working v1.0** do not take the Barkskin branch and have zero observed source refusals in this bounded fixture; they do **not** provide the same automation, and no tank survival/DPS/TPS comparison exists.

In synthetic **no-client-aggro** at 4yd, v1.5 and v1.6 both used Barkskin once (1.8s) when Defensives was ON; the source world **still has two attackers** and therefore client `aggro=false` is not reliable proof of safety. This could be a wasted cooldown or useful splash-damage prevention. Do not invent hidden health/TTD/damage-to-player or mandate a potentially unsafe `aggro` gate. Native user Defensives OFF = zero Barkskin; 6yd = zero casts due existing `target.within5`, with no 6yd three-press proof. Actual level-44 unlock, rank, target range, real game cooldown, tank damage and mitigation, PvE bosses, multi-target and Maul-at-35+ Rage still require risk-proportionate gameplay.
