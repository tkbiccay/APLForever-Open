# Project charter

APLForever is a private library of independently designed custom APLs, research evidence, tests, historical revisions, and known limitations. It is not a Hekili Forever fork.

**Primary engineering outcome (18 November 2026):** the strongest safe, working, adaptive, self-contained APLs running on the **released Hekili Forever interpreter and Belief/observation layer**, not high simulator DPS. Build and source-native test priorities, real casts/refusals, procs, toggles, level/unlocks, uncertainty, defensive safety and complete repeated fallback; refine before requesting scarce live validation. **WoWSims/SimC/Raidbots/AskMrRobot-style numerical DPS/Tank/Healer simulation is optional, deferred unless a specific consequential APL decision warrants verified modelling**, and must never displace APL work. Reuse development-time simulation/test methodology across appropriate roles without shared APL runtime files. [Detailed role/simulation policy](knowledge/SIMULATION_POLICY.md). All authorised GitHub-connected agents, regardless of model/vendor, follow AGENTS.md and the live continuation handover; prior chat memory is not authoritative.

**Standalone runtime guarantee:** Every role's delivered APL is one complete text file that runs using only its own action lists and verified Hekili Forever built-in engine/registered game states and APIs. It must not require another APL, cross-profile action list, runtime helper file, or shared custom library. We share issue resolutions, methods, test harnesses and evidence **during development only**, and reimplement verified improvements inside each self-contained APL with its own role-specific guards and final fallback.

The project favours creative, self-contained combat control where supported, with minimal reliance on per-spec settings. **Every APL is identified as `<Class>_<Spec>` and optimises one declared spec and primary role; verified Forever hybrid talent builds and same-role ranged/melee weaving are allowed.** **Default architecture: ONE adaptive preferred APL per supported class/spec/role, covering levels 1–60 and continuing to work at level 60 for open-world, dungeons and raids. A level-60 character questing is not automatically in a raid rotation; use verified encounter/talent/setting state, never level alone as a proxy for player intent. Do not create a separate Levelling/Endgame profile as routine work.** Different designs may be evaluated as versioned candidates, and a parallel content-specific profile is an exception only where matched native and in-game evidence shows reliable adaptation cannot match it without unsafe/unobservable state, and maintenance/validation costs are justified. Role remains catalogue metadata. Preserved historical role-suffixed files must not be rewritten. Changes are evidence-based: preserve working configurations, compare candidates with defaults and prior working versions, audit the complete priority chain and final fallback, and promote only after real-world validation. Do not assume unsupported features or fabricate research, syntax, spells, APIs, benchmarks, or gameplay evidence.

ChatGPT owns class/spec mechanics research, independent role-focused APL design, including valid Forever hybrid builds, optimisation, regressions and analysis of observations. Codex is used selectively for meaningful repository engineering, parser/test integration or local execution that cannot be performed more economically here; neither replaces live user evidence. Repository tooling handles versioning, integrity, repeatable static checks, and regression protection. Leave unverified roles unknown; do not create dummy APLs.
