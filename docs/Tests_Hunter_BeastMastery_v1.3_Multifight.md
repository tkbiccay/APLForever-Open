# Hunter BM v1.3 — multi-fight source-native test (20 November 2026)

**Question:** Does our new independently gated Bestial Wrath v1.3 behave safely when six-yard combat repeats three times on the **same addon instance**, compared to protected complete BM v1.2? Previous [v0.11.0 single-fight four-case run](https://github.com/tkbiccay/APLForever-Open/actions/runs/44808310285) proved one source-accepted Bestial Wrath at 6yd without dropping Hawk; the previously [merged BM three-fight run](https://github.com/tkbiccay/APLForever-Open/actions/runs/44807982020) only tested 12yd with Major OFF (shipped, v1.1, v1.2), not the new v1.3 at 6yd with Major ON.

**Pinned engine:** published [Hekili Forever v0.11.0](https://github.com/zmsl/hekili/releases/tag/v0.11.0), commit `86b739cbc4e6afbcbc693c3790ee81197fc6234b`. Directly import each whole immutable protected v1.2 or candidate v1.3 APL, a separate original client for each, then re-use that loaded addon for three 35-second six-yard worlds (different seeds, same local ability kit; **not** a persistent Mana/cooldown world). Read `run.pressed` rather than only recommendation icons; record per-fight Hawk, Bestial Wrath, accepted follow-ons, resource tail, native world events/refusals. Six-yard Rapid Fire/ranged attacks are forbidden. At least three real accepted actions must follow the first source-accepted Hawk each pull. No fabricated pet arrival, pet damage, real game client or DPS.

**Pre-declared failure criteria:** any engine errors, source refused casts, out-of-range ranged attacks, zero Hawks, less than three legal post-Hawk actions, fewer v1.3 Hawks or accepted actions than v1.2 in a matched pull, or missing the initial candidate six-yard Bestial Wrath that motivated v1.3. These fail the experiment, preserve the exact protected v1.2 and demand root-cause investigation; never silently loosen requirements.

**Observed native result (20 November 2026):** [GitHub Actions run 44809137957](https://github.com/tkbiccay/APLForever-Open/actions/runs/44809137957) **1/1 test PASS**, covering six actual 35-second source-world fight attempts on two separately imported full APLs. For protected v1.2 each fight: 4 accepted Hawks, 0 BW, 0 Rapid Fire, 6 accepted actions, 3 post-Hawk accepted actions, 0 refused, 0 errors. For v1.3 each fight: 4 accepted Hawks, 1 accepted Bestial Wrath, 0 Rapid Fire, 7 accepted actions, 3 post-Hawk accepted actions, 0 refused, 0 errors. This confirms no six-yard regression in the **specific source-world loops**, not a real DPS gain.

**Important discovered harness limitation:** every 35-second `loop.run` fixture restarts its world/source resource pool; each of three candidate fights accepted Bestial Wrath again despite its published **120-second cooldown**, and `mana_end=3750.00` every fight. Reusing the addon object **does not demonstrate** that a real client's cooldown/mana state carries over correctly across fights. The original test only asserts per-world source castability/progression, not true across-fight cooldown persistence. **Do not claim** real three-fight resource conservation, cooldown carry-over or game approval from this PASS. A future new harness fixture would need source-true elapsed out-of-combat cooldown clock/state between pulls; the real game client is the final acceptance gate.

**Result:** Source-native Draft evidence only; preferred BM remains null, v1.1 Current and v1.2 unselected Candidate intact. Real-game pet activity, 1–60, solo/group/boss DPS and safe cooldown consumption remain unverified.
