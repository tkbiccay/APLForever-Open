# APL autonomy standard — one fully self-controlled rotation per supported Forever role

**Adopted 20 November 2026 by the maintainer, across all 28 intended roles (23 currently supported; five healer roles blocked).** This is a development/acceptance contract, not evidence that every existing candidate already conforms. The last-reported-working APL, shipped default and historical revisions remain byte-for-byte protected.

## Expected gameplay

The intended experience is **import, select and play**. Each supported, approved APL must make its own *routine* recommendations from the available source-verified Hekili Forever/Belief observations. The player should not need to visit class/spec pages or tick boxes to enable upkeep, curse/seal/poison/imbue choice, normal damage, pet recovery, forms/stances, threat/mitigation maintenance, safe resource conversion, target-mode choice or final fallback. These decisions belong in that role's complete standalone priority — no shared Lua files, cross-APL helpers or custom runtime add-ons.

**Important distinction:** Hekili's generic toggles can be *user off-switches*, not a hidden prerequisite to a functioning rotation. The upstream [v0.10.0 Toggles documentation](https://github.com/zmsl/hekili/blob/v0.10.0/docs/wiki/Toggles.md) states an ability's **Require Toggle** assignment makes it unusable whenever that toggle is OFF, even if an APL line has no `if=toggle.*`. A pure APL **cannot override this engine contract**. Therefore respect a deliberate player OFF, use source-registered categories honestly and document an unavoidable engine restriction; do **not** promise all Major/Minor/Defensive/Interrupt/Potion abilities will trigger with their off-switches OFF.

## Design rules

1. **Zero manual dependency for routine decisions.** A newly authored APL must not use a `settings.<key>` per-spec dropdown or checkbox as the *condition required to make its normal rotation work*. Prefer observed ability knowledge, cost, aura status, proc, combat mode, threat, pet/form, attack eligibility and conservative resources. A test must run with stock defaults, no user activation. Never add an arbitrary custom setting to make a suggested recommendation possible.
2. **Automatic upkeep, not spam.** Debuffs, buffs, auras, seals, poisons and pet states use verified eligibility, refresh thresholds, resources and appropriate encounter value. Short solo fights, long bosses, grouped tanking, range uncertainty and low-level kits differ. Avoid overcasting 10-Rage or full-GCD upkeep on disposable mobs or repeated unsafe fallbacks.
3. **Automatic optional ability timing when allowed.** Design Major/Minor cooldowns, defensives, movement and interrupts around actual mechanics rather than requiring the player to choose timing by tick boxes; *still* respect explicit OFF and native Require Toggle restrictions, separate optional utility/potions from ordinary rotation. Do not hide a necessary throughput filler, pet recovery or routine tank debuff behind an optional cooldown toggle. For hidden/secret combat state, fail safe or document that a tactical ability remains manual.
4. **AoE is observability-limited.** Use `active_enemies` and known target/count/range signals where truthful. In instances and with absent nameplates Hekili may only report 1 target; the APL cannot secretly detect enemies. Document the real need for manual display/target-mode correction rather than pretending fully automatic AoE always works.
5. **No invented reads, no blanket changes.** Use the [pinned Forever APL conditions](https://github.com/zmsl/hekili/blob/v0.10.0/docs/wiki/APL-Conditions-On-Forever.md), exact registered abilities and fallback semantics. `target.is_boss`, `tanking`, `time`, `target.within5`, estimated Rage and hidden health have documented limitations. Test source-native first; no unmeasured DPS/survival improvements.
6. **Fully standalone import.** Every action/list/fallback and talent/rank/level branch lives inside that APL's own import file. No other role's APL, external helper or optional plugin should be necessary for castability.
7. **Respect the user's choices.** The player need not manage tick boxes to run the normal rotation. But actively disabling Major/Minor, Defensive, Interrupt, Movement, Potions or a named ability is a real opt-out, not permission for the APL to ignore consent or override the engine's setting.

## Mandatory all-role audit and promotion gates

- The repository's `scripts/audit_apl_controls.py` scans **every catalogue revision**, not just the newest, for `settings.*` and `toggle.*`. All previously reported uses are tied to **exact protected path and SHA-256**; a brand-new unreviewed `settings.*` dependency fails the static guard. Historical baseline exemption is *not* a certificate of autonomously correct behaviour. Toggle occurrences are **review findings**, not automatic defects; classify each ability and call-site by role/function.
- Prioritise **Guardian and Hunter BM equally**, followed by Feral DPS and risk-ranked roles. Check inherited old-state references before spending credit. Guardian v1.0 and Demonology v1.0 are user-reported working rollbacks: DO NOT rewrite their exact source merely to pass this new policy. Build independent full candidate, test against shipped/default and last working and preserve hashes.
- Guardian v1.2 gates routine Demoralising Roar behind Defensives, while v1.3 historically used `settings.maintain_demoralizing_roar`; **v1.4 Draft** replaces both with an autonomous source-visible boss/grouped/long-solo policy. Its focused 24-case v0.10.0 gate passed, but its broader v0.9.0 import lane **FAILED**, so it is *not* fully validated or ready for promotion. Hunter BM pet recovery/temporary guardians remain their own separate evidence gate. Demonology's assigned curse currently uses a class-setting dropdown; evaluate independent safe curse choice with the source's debuff/debuff-slot/group mechanics before creating a new candidate.
- Special high-value review: Paladin Protection's Holy Shield currently has a Defensives guard; assess whether this is **core mitigation** incorrectly hidden behind an optional toggle. Druid Balance, Mage Arcane/Fire/Frost and Elemental/Enhancement Shaman place some mana recovery under `toggle.cooldowns`; inspect the exact named resource action before changing, since registered cooldowns may be deliberately controlled by the engine. Also check any damage/utility moves under Movement or Minor Cooldowns; don't falsely call all toggles bugs.
- **Each changed role** must show default/no-manual-setup source-native imports, all option OFF/ON comparisons, honest engine-owned Require Toggle handling, 1–60 unlocks, resource extremes, ST/2/3+ when observable, opener, three source-accepted subsequent recommendations, **Final Fallback / Repeated Recommendation**, and shortest necessary in-game evidence. Anything unobservable is **Engine Limitation / Needs In-Game**, never a fabricated native PASS. No mass auto-promotion and no forced spec-wide rewrite.
